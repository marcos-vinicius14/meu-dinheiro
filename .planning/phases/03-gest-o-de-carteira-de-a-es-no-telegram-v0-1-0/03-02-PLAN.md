# Plan 03-02: Comandos de Carteira, Aporte e Venda com Callbacks Inline e Suporte a Renda Fixa no Bot Telegram

## Objetivo

Implementar a camada completa de interação do investidor no Bot do Telegram (`apps/bot`):
1. Expansão de sintaxe de tickers no parser para suportar ativos da B3 e títulos de Renda Fixa (`TD-SELIC`, `CDB-INTER`, `TD-IPCA29`) de até 12 caracteres (D-17).
2. Novo parser `ParseSaleCommand` aceitando sintaxe flexível de baixa com preço de venda opcional (D-05).
3. Visualização consolidada em `/carteira` (aliases `/investimentos`, `/portfolio`) com cards de 2 linhas por papel, ordenação por maior volume financeiro investido (R$), % de alocação, totais globais no rodapé, botões de ação rápida `[➕ Novo Aporte]` e `[🔄 Atualizar]` (in-place edit), e card amigável para carteira vazia (D-01..D-04, D-12, D-14).
4. Comandos de aporte `/investimento`, `/comprar`, `/aporte` com recálculo de Preço Médio e cards educativos quando sem argumentos (INVEST-01, D-15, D-16).
5. Comandos de venda `/venda`, `/vender` com apuração de Lucro/Prejuízo (R$ e %), botões de crédito no saldo bancário (`[💳 Creditar R$ X no Saldo Líquido]`), bloqueio defensivo de excesso com atalho `[Vender Todas as X]`, encerramento de posição zerada e reversão efêmera `[↩️ Desfazer Venda]` (INVEST-03, D-05..D-10, D-15, D-16).
6. Preservação integral do teclado persistente 2x2 da Fase 2 (D-13).

## Threat Model (ASVS L1)

<threat_model>
| ID | Threat Type | Description | Mitigation Strategy |
|---|---|---|---|
| T-03-05 | Negação de Serviço / ReDoS em Regex (ASVS V5.1) | Expressões regulares complexas causando estouro de CPU ao processar tickers arbitrários do usuário. | Regex estritamente delimitado e ancorado `^[A-Z0-9.\-_]{1,12}$`; não utiliza quantificadores aninhados nem retrocesso catastrófico. |
| T-03-06 | Adulteração de Callback Query / Parameter Tampering (ASVS V4.2) | Manipulação dos dados trafegados nos botões inline (`invest:credit:...`, `invest:undo:...`) para creditar valores inexistentes ou em contas de outros usuários. | O bot extrai o usuário estritamente de `cb.From.ID` (Telegram autenticado) e valida os parâmetros dos tokens contra os limites numéricos antes de invocar a API com chave interna. |
| T-03-07 | Corrupção de Estado por Cliques Repetidos (ASVS V5.1) | Usuário clica repetidas vezes no botão de crédito de saldo gerando múltiplos depósitos. | O handler de callback remove ou substitui o markup da mensagem imediatamente após a execução, notificando o usuário que a ação já foi processada. |
| T-03-08 | Injeção de Valores Negativos no Parser de Venda (ASVS V5.1) | Usuário tenta enviar preços ou quantidades negativas via `/venda TICKER -10 a -50` gerando cálculos absurdos de lucro/prejuízo. | `ParseSaleCommand` valida estritamente `qty > 0` e `price >= 0`, rejeitando inputs inválidos com mensagens explicativas em pt-BR. |
</threat_model>

   - Atualizar a definição de `tickerRegex`:
     ```go
     tickerRegex = regexp.MustCompile(`^[A-Z0-9.\-_]{1,12}$`)
     ```
     permitindo tickers de 1 a 12 caracteres contendo letras, dígitos, ponto, hífen e underscore (D-17).
   - Implementar `ParseSaleCommand(args string) (ticker string, qty float64, price *float64, err error)`:
     - Normalizar `raw := strings.TrimSpace(args)`. Se vazio, retornar erro amigável `"Argumentos obrigatórios ausentes. Envie no formato: /venda <TICKER> <QUANTIDADE> [a <PREÇO>]"`.
     - Normalizar separadores com `letterCommaRe` e `commaSpaceRe`.
     - Tokenizar com `strings.Fields`.
     - Iterar tokens:
       - Ignorar tokens sintáticos: `"un"`, `"unidades"`, `"cotas"`, `"cota"`, `"a"`, `"de"`, `"r$"`.
       - Tentar parsear token como float positivo/zero via `ParseMoney`. Se sucesso, adicionar em slice de números `nums []float64`.
       - Caso contrário, converter para maiúsculo. Se casar com `tickerRegex` e `ticker == ""`, atribuir a `ticker`.
     - Validações:
       - Se `ticker == ""`: retornar erro `"Código do ativo (ticker) não informado ou inválido."`
       - Se `len(nums) == 0`: retornar erro `"Informe a quantidade a ser vendida. Exemplo: /venda TICKER QUANTIDADE [a PREÇO]"`
       - `qty = nums[0]`. Se `qty <= 0`: retornar erro `"Quantidade deve ser maior que zero."`
       - Se `len(nums) >= 2`:
         - `priceVal := nums[1]`
         - Se `priceVal < 0`: retornar erro `"Preço de venda não pode ser negativo."`
         - `price = &priceVal`
     - Retornar `(ticker, qty, price, nil)`.
</action>
