# Plan 03-01: Endpoints Internos de Listagem Consolidada e Venda de Investimentos com Suporte no APIClient

## Objetivo

Expor na API Go (`apps/api`) os novos endpoints internos autenticados por cabeçalho secreto (`X-Internal-Secret`):
1. `GET /internal/investments?telegram_id=...` para consulta consolidada da carteira de ativos, custo total investido, saldo bancário líquido e patrimônio líquido global.
2. `POST /internal/investments/sell` para baixa atômica de custódia, remoção de posição zerada e recálculo das métricas de patrimônio.

Validar a camada de persistência e regras de negócio com testes de integração reais contra PostgreSQL 18 via Testcontainers (sem mocks de banco), e disponibilizar os métodos e DTOs correspondentes no `client.APIClient` do bot (`apps/bot`) com testes unitários cobrindo serialização e tratamento de erros.

## Threat Model (ASVS L1)

<threat_model>
| ID | Threat Type | Description | Mitigation Strategy |
|---|---|---|---|
| T-03-01 | Acesso Não Autorizado / Bypassing Auth (ASVS V4.1) | Requisições aos novos endpoints sem o cabeçalho secreto interno acessando dados sensíveis de patrimônio. | Middleware `requireInternalSecret` exige `X-Internal-Secret` ou `X-Internal-API-Key` correspondente; retorna HTTP 403 Forbidden imediato se inválido ou ausente. |
| T-03-02 | Condição de Corrida / Venda Duplicada (ASVS V5.1) | Vendas concorrentes do mesmo ativo tentando baixar mais quantidade do que a custódia disponível gerando saldo negativo. | `repository.Sell` utiliza transação `database.WithTx` com `SELECT ... FOR UPDATE` no PostgreSQL 18; validação de quantidade rejeita excessos com `ErrInsufficientQuantity` (HTTP 400). |
| T-03-03 | Injeção de Parâmetros / Quantidade Inválida (ASVS V5.1) | Envio de quantidades negativas ou zero em `POST /internal/investments/sell` causando distorção contábil. | Validação estrita do payload no handler: `req.Quantity.IsPositive()`; rejeita com HTTP 400 se `quantity <= 0`. |
| T-03-04 | Imprecisão de Ponto Flutuante Monetário (ASVS V5.1) | Perda de centavos em cálculos de patrimônio e preço médio. | Toda manipulação na API utiliza tipos nativos `money.Money` e `decimal.Decimal` com Banker's rounding HalfEven (`RoundBank(2)`). |
</threat_model>

## Must Haves

<must_haves>
### Truths
- `GET /internal/investments?telegram_id=...` retorna a lista de posições ativas do usuário e a consolidação do patrimônio líquido global somando o total investido ao saldo líquido bancário (D-01, D-03).
- `POST /internal/investments/sell` abate atomicamente a quantidade informada mantendo o Preço Médio inalterado, e remove o registro do banco quando a posição é 100% zerada (D-09, D-12).
- Recompra de ativo zerado inicia um novo ciclo limpo onde o novo PM é estritamente o preço da nova compra (D-11).
- Todos os endpoints exigem cabeçalho `X-Internal-Secret` e retornam 403 Forbidden se ausente ou incorreto (T-03-01).
- Todos os testes de integração backend rodam contra PostgreSQL 18 real via Testcontainers sem mocks de banco.

### Artifacts this phase produces
- `apps/api/internal/botapi/investment.go`: Handlers `handleListInvestments` e `handleSellInvestment` com seus respectivos DTOs.
- `apps/api/internal/botapi/handler.go`: Registro das rotas internas no roteador Chi.
- `apps/api/tests/integration/internal_bot_api_investment_test.go`: Bateria de testes de integração com Testcontainers cobrindo listagem, venda, erro e ciclo de recompra.
- `apps/bot/internal/client/types.go`: Structs `InvestmentItem`, `ListInvestmentsResponse`, `SellInvestmentRequest`, `SellInvestmentResponse`.
- `apps/bot/internal/client/api_client.go`: Métodos `ListInvestments` e `SellInvestment`.
- `apps/bot/internal/client/api_client_test.go`: Testes unitários dos novos métodos do cliente.

### Prohibitions
- Não utilizar mocks de banco de dados (`sqlmock`) em nenhuma etapa.
- Não usar `float64` nas operações financeiras dentro da API (`apps/api`), preservando `money.Money` com Banker's rounding HalfEven.
- Não permitir venda com quantidade menor ou igual a zero nem venda de quantidade superior à custódia atual.
</must_haves>
